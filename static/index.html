SCHEMA ARCHITECTURE

How Acoustic Annotations Link to Metadata & Cloud Audio

Find & Filter Guide ↗ Schema Reference ↗

nmfs_annotation_db unites authoritative deployment metadata from Makara with physical hydrophone containers in Google Cloud Storage (gs://). Annotations in core.annotations store indexed UTC time bounds (tstzrange), frequency bounds (freqrange), verification labels (YES, NO, MAYBE, UNVERIFIED), and steward organization_code.

Why annotations link to recording_channel_id instead of a single filename: HARP .x.wav / .x.flac containers pack dozens of raw subfiles inside one object, multi-channel MARUs separate deployments by channel, and continuous calls can span consecutive files. Joining via PostgreSQL GiST temporal overlap (seg.tstzrange && a.tstzrange) resolves exact cloud URIs and byte offsets in milliseconds.

Working Dataset & Crawler Whitelist: Try the populated NEFSC North Atlantic Right Whale dataset (effort = DCLDE_2013, 5,649 verified upcalls). Because GCS uses Autoclass storage, if a recording you need isn't crawled yet, ask Dan to add it to the crawler whitelist.
